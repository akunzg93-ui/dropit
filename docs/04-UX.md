# Objetivo

Definir una experiencia consistente para todas las pantallas de Dropit.

El usuario nunca debe sentir que cambió de aplicación al navegar entre módulos.

---

# Principios

- Simplicidad antes que decoración.
- Una acción principal por pantalla.
- La información importante debe verse primero.
- Reducir la cantidad de clics.
- Mantener consistencia visual.

# Iconografía

Se utilizará Lucide Icons como librería oficial.

---

# Logo

El logo deberá mantenerse visible en las pantallas principales.

No deberá reducirse innecesariamente.

---

# Terminología

Utilizar siempre:

- Cliente
- Vendedor
- Establecimiento
- Administrador

No utilizar "Comprador" en la interfaz.

---

# Mensajes

Los mensajes deben ser:

- Claros.
- Breves.
- Accionables.

Evitar mensajes técnicos al usuario.

---

# Responsive

Todas las pantallas deberán funcionar correctamente en:

- Móvil.
- Tablet.
- Escritorio.

---

# Consistencia

Cuando se cree una nueva pantalla deberá reutilizar los componentes existentes antes de crear nuevos.

# Onboarding contextual

Dropit explica las funciones importantes cuando el usuario las necesita por primera vez y después evita interrumpir innecesariamente su operación.

El onboarding educativo debe:

- aparecer en el contexto de la funcionalidad que explica;
- ser breve y accionable;
- poder completarse u omitirse;
- persistir su estado cuando corresponda;
- poder versionarse cuando una funcionalidad cambie sustancialmente.

Omitir un onboarding educativo cuenta como experiencia vista y no debe provocar que reaparezca indefinidamente.

El onboarding educativo es independiente de requisitos operativos, fiscales o legales.

# Sistema de modales

Dropit utiliza familias de modales según su propósito.

## FlowGuideModal

Se utiliza para hitos, confirmaciones y siguientes pasos relevantes, por ejemplo pedido creado, punto confirmado, pedido aceptado o establecimiento registrado. Puede incluir encabezado de éxito, dato principal, pasos siguientes, recomendación y acciones.

## OnboardingModal

Se utiliza para educación de primera vez. Debe permitir progreso por pasos, avanzar, regresar, omitir y finalizar. En móvil puede comportarse como bottom sheet y en escritorio como modal centrado.

## Confirmaciones compactas

Las acciones operativas que sólo requieren confirmación o una instrucción breve no deben forzarse dentro de los modales anteriores.

Todas las familias deben conservar el mismo lenguaje visual de Dropit sin obligarlas a compartir exactamente la misma estructura.
